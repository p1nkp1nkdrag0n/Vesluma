# Vesluma

以地标激活、区域揭雾和旅行记录为核心，支持个人探索与小队同行的城市探索记录应用。

> Uncover the city. Keep the memories.<br>
> 展开一座城，留下这一程。

当前已实现可运行的手机 MVP 原型，并已将地图方案 0.2 接入代码：未解锁区显示真实主干道骨架，默认 C 纸感，可选藏宝图；已解锁区显示原始真实详细底图。测试城市采用南京和西安，使用 React / TypeScript / Vite，附带 Capacitor iOS / Android 工程与 PWA。城市区划及拍照点仍需现场核实；本地身份、小队和公开相册尚未连接云服务。

## 本地运行

```sh
npm install
npm run dev
```

打开 [本地应用](http://localhost:5173/)。桌面展示固定比例手机画面，基准为 **402 × 874**，对应 [Apple iPhone 18 Pro 的 1206 × 2622 屏幕比例](https://www.apple.com/iphone-18-pro/specs/)；手机浏览器使用实际视口与安全区域。

默认进入明确标注的演示位置模式。开始旅行后，打开任意地标 → 拍照激活 → 选择本地照片或示例图片 → 模拟抵达此地 → 保存并展开地图。示例图片、示意区划与演示到访会分别标记。设备模式请求实际定位，相机与照片选择在原生工程中接入 Capacitor 插件；设备定位校验仍使用待核实的候选坐标和 250 米原型到场范围。

## 已确认的地图调整

最新 [MVP 方案 0.2](docs/mvp-design.md) 采用“未解锁主干道简图 + 已解锁真实详细地图”：

- 未解锁区显示真实主干道、必要路名与主要水域轮廓，以 C 纸感风格为默认方向、藏宝图为可选主题；支路、街巷、建筑与普通 POI 继续隐藏。
- 已解锁区保留真实详细底图与路网。纸纹、仿旧、水彩等主题效果仅应用于未解锁层，不覆盖真实底图，也不改动道路位置和连通关系。
- 激活前后主干道原位衔接；浏览骨架、切换主题均不产生激活、到访或进度变化。点云、永久权益与重访规则延续。

地图分层、主题选择、每个本地身份的主题偏好和回放显示已接入原型。入口为探索地图上的调色盘按钮，或“我的 → 地图显示主题”。主干道与水域使用随应用打包的 OSM 真实几何快照，按城市加载；两套主题在已解锁范围完全裁掉，底图不经过主题滤镜。旧 v1 记录与备份自动补默认纸感主题，保留照片、足迹和永久权益。参考图中的已展开部分仍是生成示意，不作为真实路网配置。

## 已实现的闭环（现有原型）

- 南京 6 个候选地标 / 5 个示意区，西安 5 个候选地标 / 4 个示意区。夫子庙与老门东、钟楼与鼓楼分别共用区块，区块权益与地标首次激活独立判断。
- 真实 WGS84 主干道／水域骨架、可缩放拖动、纸感和藏宝图主题、真实详细底图的区块展开、未开放测试或骨架未覆盖区域的独立标识。默认详细底图为 OpenStreetMap；配置 `VITE_CARTO_API_KEY` 可使用 CARTO 浅色底图。自定义底图必须与 WGS84 / Web Mercator 兼容，不能把 GCJ-02 或 BD-09 瓦片直接替换并声称坐标已对齐。
- 近远地标排序、明确的直线距离、目标指南针。方向传感器需主动启用；未获得可靠朝向时使用北向参考。选择目标和查看照片均不揭雾。
- 图片保存在 IndexedDB，事件与区块权益保存在 localStorage。提交标识去重，首次激活与每次重访分别保存；结束、跨城与本地身份切换均不重置已获得权益。
- 两个本地身份、小队邀请代码、一次上传共享、加入时刻与离队边界、临时独行。旧个人进度不自动复制，独行照片默认私密，个人位置点不共享。
- 旅行归档、真实采样点云、时间游标回放与相册；主动公开单条照片及撤下；含照片的完整 JSON 备份导出与恢复。
- PWA 缓存应用、本地素材与两城主干道快照，首次完成缓存后可离线启动并切换城市、主题；远端详细地图瓦片不预缓存，断网不承诺新的详细底图可用。真实图片纹理压缩为 WebP，两套合计约 143 KB；真实地理数据不在纸纹图片中。

这些能力属于**本地交互原型**。真实账号认证、跨设备自动恢复、云空间上传、多人网络同步与全网公开相册尚未实现。用户照片不会通过当前原型上传网络。

前台定位按速度以 5 / 10 / 30 秒间隔筛选实际取得的位置点；暂停、无有效位置或非前台时不补点、不连线。该实现用于本地体验，不替代仍待设计的正式定位生命周期，也不承诺锁屏或后台记录。

## 构建与验证

```sh
npm test
npm run build
npm run native:sync
npm run preview
```

65 项单元验收覆盖永久进度、双城与身份隔离、首次与重访、小队共享、位置校验、历史回放、损坏备份，以及真实几何、源数据筛选、异步加载／重试、主题迁移、区域并集和标签避让。浏览器复验覆盖主题切换、激活前后、缩放拖动、旧记录与两个身份、两城离线骨架。已解锁内部的主题画布 alpha 在 C／藏宝图均为 0，未解锁内部为 255；切换主题时详细底图 URL 保持不变。

应用入口代码、React 运行时和地图引擎分别打包；两城 JSON 作为独立资源，按需读取并缓存。可复现数据导入、许可及坐标限制见[地图数据来源](docs/map-data-provenance.md)。

`android/` 与 `ios/` 已生成并同步构建资源，原生图标与权限声明已配置。iOS 工程使用 Swift Package Manager。尚未编译、签名或实机验证 APK / IPA；iOS 运行需要 macOS 与 Xcode，Android 运行需要对应 SDK。详见[原生工程说明](docs/native-projects.md)。

## 核心规则

- 地标由近及远展示，目标指南针提供方向，用户自主选择如何移动。
- 未解锁区保留真实主干道简图，隐藏详细道路；到访地标后展开按现实结构划分的真实详细底图。C 纸感和可选藏宝图主题只影响未解锁区。
- 实际足迹以定位点呈现，不连接成路线。
- 小队打卡只上传一次，云端保存默认不公开，公开分享由用户主动选择。
- 开图进度永久保留，重访不重置；首次激活与重访记录的具体方式见 MVP 设计建议。
- 持续定位的范围和生命周期后续专门设计。

资料中的原对话链接用于保留来源，需要相应的会话访问权限；产品规则和设计内容已经整理在本仓库中。
