# Vesluma MVP 设计：南京 × 西安

版本：0.2 · 2026-09-30。阶段：地图分层与主题规则已接入本地手机原型；主干道采用真实 OSM 快照，区划与拍照点仍待现场核实，云端共享和实机发行仍未完成。

依据：[产品基线](product-baseline.md)、用户批注及本轮地图方向确认。测试城市为南京、西安。用户已确认：未解锁区提供手绘主干道简图，以 C 纸感地图为主方向，藏宝图作为可选主题；已经展开的区域必须保持真实详细底图与路网。其余页面安排、小队边界、首批地标数量、测试规模和技术组织仍为 MVP 设计建议，不混同为用户逐项确认的需求。

## 1. 首版目标与范围

让用户在南京或西安完成一次个人或小队旅行：通过始终可见的真实主干道简图判断方向，从地标出发、拍照激活真实区划、展开真实详细底图，在未展开区域继续留下位置点、选择下一个目标、回看照片和开图过程。下次旅行继续使用永久保留的开图进度。主干道已经可见不计入开图进度，激活获得的是对应区域的详细地图。

采用同一个账号、同一套界面和流程、两份城市内容配置。南京与西安进度分别累计；城市切换不清空记录。本轮按手机使用场景设计，延续 iPhone 18 Pro 的 402 × 874 展示比例。本地原型已有 React / TypeScript、Vite 与 Capacitor 工程；正式云端账号、同步及实机发行仍需后续落实。

本轮已明确：

- 地标由近及远展示；此前“由远及近”为口误。
- 开图进度永久保留。
- 重访不重置地图。
- 未解锁区从完全遮挡改为主干道简图；道路实际位置、走向与连通关系保持真实，手绘只改变视觉笔触。
- C 纸感地图作为默认方向，藏宝图作为可选主题；两者仅作用于未解锁简图，已展开区显示真实详细底图与真实路网。
- 持续定位的范围与生命周期后续专门解决。本稿不固定全天候、仅旅行期间、锁屏、启动和结束采样策略；“开始／结束旅行”暂指档案归属，不能据此偷定定位策略。
- “首次激活与后续到访分别保存”先解释，并作为本稿的重访建议，不声称用户已确认。

### MVP 必须包含

| 能力 | 最小实现 |
|---|---|
| 账号与双城 | 一个轻量账号入口、南京／西安切换、各城永久进度；真实内测支持跨设备恢复 |
| 探索地图 | 未解锁区的真实主干道简图、已解锁区的真实详细底图、配置区划、缩放拖动、地标与本人位置点 |
| 地图主题 | 默认 C 纸感简图、可选藏宝图；切换只改变未解锁层的样式，不改变已解锁底图、数据和开图状态 |
| 目标选择 | 地标由近及远浏览、设为目标、指南针和明确标注的直线距离 |
| 地标打卡 | 合影、已有位置的基础校验、一次提交、照片及事件保存、对应区域展开 |
| 点云记录 | 保存实际取得的位置点和时间，在迷雾中也显示；不连线、不补路 |
| 个人与小队 | 创建／加入、一人上传、共同记录关联成员、临时独行与恢复同行 |
| 永久进度 | 跨次旅行、城市切换及重新登录后保留；重访不重置 |
| 旅行回顾 | 同一旅行的地图、时间顺序、照片；按地标查看关联记录 |
| 最小公开打卡 | 原上传者主动公开一条内容到地标、他人查看、可撤下；默认保存在个人／小队空间 |
| 城市内容配置 | 地标档案、到场范围、区域多边形、激活关系、试验范围和现场核实状态 |

首版暂缓：独立社区信息流、推荐算法、点赞关注、聊天、排行榜、等级任务、视频与语音日记、完整人生档案、全功能运营后台。公开打卡保留最小闭环，不扩张成社区。定位生命周期按用户要求另议，不作为本轮产品讨论的前置问题。

## 2. “首次激活与后续到访分别保存”是什么意思

推荐采用“一个持续有效的开图状态，附带多次到访记录”。

例如以下均为说明用的虚构记录：

| 时刻 | 用户动作 | 照片与记录 | 地图结果 |
|---|---|---|---|
| 第 1 天 10:20 | 第一次在南京夫子庙打卡 | 保存合影 A 和这次到访；记下首次激活时间 | 对应区域首次展开 |
| 第 3 天 15:40 | 又来到夫子庙，主动保存一张新合影 | 增加合影 B 和第二次到访；第一次照片仍在 | 地图继续展开，首次激活时间仍是第 1 天 10:20 |

“分别保存”指不覆盖以前的经历，不要求用户建两个相册，也不让用户在两套打卡模式之间选择。地标详情里可以看到：

> 夫子庙 · 已激活<br>
> 首次激活：第 1 天 10:20<br>
> 到访记录：第 1 天的合影 A、第 3 天的合影 B

建议按钮根据状态显示“拍照激活”或“记录这次到访”，底层使用同一提交流程。重访记录只在用户主动提交时增加，路过不自动生成一次到访；后台自动检测与定位生命周期均不在本稿决定。

若用户已经通过小队获得某区域，再亲自来到地标，可新增本人的到访记录，不重开该区域。界面分别表达“小队展开了这里”和“本次到访”，不把共享获得区域推断成所有成员当时在场。

## 3. 南京与西安的试验内容

建议南京首批 6 个候选地标；西安首批 5 个、另留 1 个扩展候选。先对每城核心组完成现场核实，至少配置两个相邻可展开区域以测试真实边缘。最终区块数量、形状和地标关联由勘察决定，不为了凑数量画区。

这些分组服务于测试组织，不是推荐路线，不约束用户访问顺序。每座城市最终全城可解锁的目标保持不变。MVP 中区分“已展开详细地图”“本次可解锁、目前仅显示主干道简图”“尚未纳入地标测试”三种状态；未配置区不伪装成已经具有激活规则的区域。城市基础数据覆盖内的未测试区域可以显示主干道骨架，仍明确提示未开放地标开图，也不进入试验区进度分母。

进度文案使用“已展开 3 个试验区”等实际配置统计，不把少量地标的完成度称作全城完成率，也不虚构全城区域分母。

## 4. 页面与关键交互

建议底部只保留三个一级入口：探索、旅程、我的。地图是默认首页；小队嵌入当前旅行，公开打卡嵌入地标详情。

| 页面／组件 | 信息层级与核心动作 |
|---|---|
| 探索首页 | 顶部城市切换及当前旅行状态；中部显示主干道简图与已展开真实底图；浮层显示目标指南针；底部可收起地标列表 |
| 地图显示设置 | 切换 C 纸感／藏宝图主题；选项注明仅改变未解锁区域的显示样式 |
| 地标列表 | 根据最近有效位置按直线距离由近及远；条目有名称、激活状态、直线距离；地图点位始终在实际位置 |
| 地标详情底部面板 | 地标名称与介绍、本人／小队记录、公开照片；主按钮拍照激活或记录到访；次按钮设为目标 |
| 打卡提交页 | 合影预览、当前地标、位置校验状态、个人或本次小队归属；一次提交 |
| 揭雾反馈 | 只展开关联区域；点的位置保持不变；显示地标、激活时间和已保存状态；可留在地图或选择下一目标 |
| 当前旅行 | 个人／小队模式、成员、同行／独行状态、照片和事件、同步状态；结束旅行形成归档 |
| 旅行回顾 | 默认地图加时间顺序；点选地标或照片互相定位；切换相册；显示本次记录和本次开图变化 |
| 我的 | 南京和西安的长期进度、历次旅行、个人相册入口；可查看既有地图并开始新旅行 |

### 探索首页的布局意图

顶部保持轻量：左侧当前城市，右侧本次旅行。地图占据主要视野；底部面板折叠时显示当前选中目标和一个主动作，展开后显示由近及远的地标。指南针只在选择目标后出现。

未展开区显示主干道简图，隐藏支路、街巷、建筑轮廓、普通店铺和详细底图；已展开区显示真实详细底图与真实路网。地标和实际采样点始终绘制在这两种地图之上。地图拖动或缩放时这套可见性始终一致；主干道可见、选目标和浏览照片都不触发开图。可使用“主干道可见 · 抵达展开街巷”的简洁图例说明信息层级。

### 地图分层与主题：本轮确认的修改

地图提供连续可读的城市骨架，让用户在应用内了解主要通路、路口和目标方位。MVP 保留自主读图与目标指南针，不新增自动最优路线、逐路口指令或基于简图推算的步行用时。

| 内容 | 未解锁区域：主干道简图 | 已解锁区域：真实详细地图 |
|---|---|---|
| 主干道及必要路名 | 可见，采用真实几何与连通关系，按主题渲染 | 可见，使用真实详细底图的道路配置 |
| 支路、街巷、建筑与普通 POI | 隐藏，放大也不额外泄露 | 按真实地图数据及缩放级别正常展示 |
| 主要水域轮廓与必要方位参照 | 可按真实形状简化显示 | 按真实详细底图显示 |
| 地标、本人位置与已采集点 | 可见，位置保持真实；足迹不连线 | 可见，与详细底图正确对齐 |
| 纸感／藏宝图笔触与纸纹 | 使用所选主题 | 不覆盖真实底图，不套水彩、仿旧或纸纹滤镜 |
| 开图状态 | 仍未展开，仅具备基础读图信息 | 已取得并永久保留该区域权益 |

**真实路网是两层地图共同的基础。** 主干道简图从真实地理数据筛选，与详细底图采用同一来源或经过核对的兼容数据，保持一致坐标系。手绘效果只能调整线条颜色、纹理、端点样式和背景材质，不能移动道路或地标、重画路口关系、虚构跨河通路，或把立交的视觉交叉误画成可转向的平面交叉。桥梁及通行限制需要保留必要信息。主干道筛选按城市内容配置核实，概念图中的 3–4 条路不构成实际城市的固定数量上限。

**激活前后，原有主干道原位衔接。** 到访后只将关联区域从简图切换为真实详细底图；同一路段、路口、水域边界和采样点不跳位。展开范围继续按现场核实的道路、河流等边界配置，不改成固定半径圆。区域边缘不得露出邻区支路，也不得用主题底色、纸纹或边框遮住已展开区域的真实路网与文字。

**默认 C，藏宝图可选。** 默认采用 C 的浅纸感、轻手绘道路与简洁水域。藏宝图采用旧纸、棕色墨线与小型复古罗盘，以 D 旧纸旅行图作为视觉参考。主题共用同一份真实骨架数据、筛选规则和地标语义，不新增宝箱、奖励、任务或连接足迹的虚构路线。E 的红色 X 等更强寻宝表达保留为视觉候选，不作为本轮必做项。主题偏好建议作为账号显示设置保存，南京与西安采用一致体验。

主题切换不改变区域权益、首次激活时间、到访记录、照片、目标或位置点；旅程回顾同样根据回放时刻的权益显示“主干道简图／真实详细地图”。实现图层建议为：真实详细底图 → 未解锁遮罩及仅限未解锁范围的主题骨架 → 地标、本人位置和点云；解锁区与主题层的遮罩须互补，不能把整个地图做成一张生成图片。

视觉参考：[C 纸感地图](map-style-reference/c-paper-concept.png)、[D 旧纸藏宝图](map-style-reference/d-treasure-concept.png)。这些图片只说明未解锁层的视觉方向，其中路网、距离及已展开部分均为生成示意；**已展开区必须直接使用真实详细底图，不能把参考图里的插画街区或生成道路作为真实配置。**

### 代码落实状态（2026-09-30）

- 两城主干道、水域与河流线已从 OSM 原始节点和几何提取，保留来源、版本、日期、桥梁／隧道和通行标签；与概念图生成道路分离。快照覆盖目前候选地标所在试验范围，详见[数据来源](map-data-provenance.md)，不代表全城已覆盖或已逐段勘察。
- 纸感／藏宝图主题共用同一数据。所有纸纹、骨架道路、水域和标签先绘制在不透明主题画布上，最后按已取得区块权益的多边形并集清除；已展开区露出未加滤镜的真实详细底图。未知／加载失败时保持遮罩，允许重试，不使用假路网补齐。
- 主题选择入口、每个身份的偏好保存、旧 v1 数据与备份默认主题迁移、旅行时间回放已接通；主题切换不改变激活、照片、目标与定位点。
- 按城市加载与失败重试已实现，PWA 在首次缓存成功后支持两城骨架及两套主题离线显示；详细在线瓦片仍与骨架缓存分别处理。
- 本地单元与浏览器验证已完成，含已展开区 alpha=0、未展开区 alpha=255 的遮罩检查。A01–A20 继续作为完整 MVP／实地验收标准；这些本地检查不替代现场道路、定位质量、云端同步及原生设备验收。

指南针旁写“直线距离”，不显示依据不足的步行用时。没有新位置时显示上次位置时间；没有可靠朝向时保留目标与距离并提示方向待更新，不假装正在实时指向。

### 三个主要流程

1. 个人：选城市 → 开始旅行 → 任意地标详情 → 合影与基本位置校验 → 提交 → 区域展开 → 选下一地标 → 回看。
2. 小队：创建或通过邀请加入本次旅行 → 一人完成打卡 → 其他当次成员看到同一条共同记录与获得的地图 → 可临时独行 → 会合或各自结束 → 各账号留存关联内容。
3. 重访建议：打开已激活地标 → 记录这次到访 → 新增照片和时间 → 地图维持已展开，首次激活时间不改。

## 5. 核心状态与异常反馈

| 对象／状态 | 处理 |
|---|---|
| 区域未展开 | 显示主题化真实主干道简图，详细道路仍隐藏；地标与采样点可见 |
| 区域已展开 | 显示真实详细底图与路网，永久保留账号权益；不随旅行结束、重访或换主题恢复简图 |
| 区域未纳入测试 | 基础数据覆盖内可显示骨架，明示未开放地标开图；不提供虚假的激活入口、不计入试验进度 |
| 地图主题改变 | 仅重绘未展开简图；已展开地图、定位点、目标和所有记录保持原状 |
| 主干道或底图数据暂不可用 | 显示加载状态并允许重试；保留地标、点和已有记录，不用生成道路补齐，也不回退显示未解锁区域的完整详细路网 |
| 当前无位置 | 地图和已有记录可查看；不展示虚构距离或宣布校验通过；允许先保留照片草稿 |
| 未通过基本位置校验 | 保留照片，说明尚未获得可用的地标附近位置，可重新获取；不加入照片鉴伪 |
| 已在本地记录、待同步 | 照片、时间和位置证据本地保存；本人可临时预览展开，标明待同步 |
| 云端提交成功 | 形成唯一事件并写入永久进度；小队成员在同步完成后获得共同内容与区域 |
| 上传失败或重试 | 保留本地内容，复用同一提交标识，不能增加重复打卡 |
| 记录缺点／中断 | 仅显示实际取得的点，不插值成行走路线；展示记录缺口 |
| 再次打卡已展开区域 | 新增经历，不重复计新增区域，不改写最早激活时间 |

本地临时展开和服务器确认的永久进度在界面上明确区分。弱网时不承诺队友已看到尚未同步的事件。不同旅行之间位置点的档案归属可切换；此设计不规定设备在旅行之外是否采样。

区域展开与地标激活分别判断。某区域已展开，不代表其中所有地标都已激活；首次在另一个地标打卡，仍保存该地标的首次事件，只是不重复增加已展开区域。按钮依据该地标的记录状态决定，不能仅依据区域是否展开。若已有与该地标关联的小队记录，显示记录到访入口并标明先前来源于小队，不声称“你曾亲自激活”。首次获得区域时间与具体打卡事件通过来源关联，不互相冒充。

## 6. 小队与公开内容的 MVP 默认方案

以下为本次建议，目的是让首版有确定、可测试的行为，后续可调整：

1. 小队绑定一次旅行，邀请后加入。共享打卡的接收成员取提交时的小队成员列表，一人上传一次即可；成员无须逐人重新上传或逐人重复确认。
2. 共同事件和照片只存一份，通过关联呈现在各成员账号。各成员的位置点保留本人归属，首版不默认提供队友实时位置图。
3. 已获得的区域进入各自城市永久进度，旅行结束或离队不收回。个人以前旅行的区域不自动复制给新队友。
4. 临时独行保留本次小队身份，继续接收小队新共享内容与开图；个人新拍内容默认仅自己，可主动分享到小队。界面标识来自小队的开图，避免写成本人到访。
5. 新加入成员从加入后参与共享；加入前的记录与权益不自动补发。彻底退出后停止接收后续共享，退出前已经关联的旅行记录保留。
6. 单条照片或打卡由原上传者控制主动公开。公开页只展示选定内容与关联地标／位置，不附带整段点集、队友位置或其他私有照片。
7. 公开内容以地标相册呈现，可撤下；撤下不删除个人／小队原记录。查看他人照片不会改变本人迷雾状态。

上述共享规则不能用小队所有人“亲自到访”之类措辞表达。轻量共享与记录归属可同时成立，不需要新增到场审查。

## 7. 城市配置与最小数据组织

首版使用内部配置表和多边形导入／预览即可，不必先做完整运营平台。发布一组试验内容前，人工检查地标与区域能否拼接、所有区块是否有有效激活关系。

| 对象 | 最小字段或关系 |
|---|---|
| 城市 | 城市 ID、名称、完整范围的定义状态、此次测试覆盖、内容版本 |
| 地标 | 独立 ID、城市 ID、名称、实际位置、简介、拍照主体、现场核实状态 |
| 地标到场范围 | 校验位置范围，与展开区划独立配置 |
| 地图区域 | 独立 ID、城市 ID、多边形、版本、对应激活地标 |
| 主干道骨架 | 道路 ID、城市、名称、道路等级、真实线几何、交汇／桥梁与必要通行属性、入选规则、数据来源／版本及核实状态 |
| 基础水域与方位参照 | 真实几何、城市归属、来源／版本；简化只降低绘制细节，不改变真实关系 |
| 地图主题偏好 | 默认 C 纸感／可选藏宝图；显示参数与地理数据、区块权益分离 |
| 旅行 | 用户或小队关联、城市、档案开始／结束时间、成员关系 |
| 打卡事件 | 唯一提交 ID、实际事件时间、同步时间、上传者、地标、照片、个人／小队来源 |
| 区域权益 | 账号、城市、区域、首次获得时间、来源事件；已获得不因旅行结束重置 |
| 位置点 | 坐标、采样时间、精度、用户和档案归属；坐标参考系明确且与地图一致 |
| 共享关联 | 原事件及提交时成员关系；个人点不被共享照片替换 |
| 公开记录 | 原内容、主动公开范围、位置关联和公开／撤下状态 |

同名地标不能仅靠名称索引；城市与区域 ID 明确归属。点、地标、校验范围、展开多边形使用一致或正确转换的坐标参考系，以免真实点落在错误街道或揭雾边缘。具体地图 SDK 和坐标转换方案留技术选型时核验。

主干道骨架与已展开详细底图也必须参与同一坐标对齐与版本核验。主干道入选范围按南京、西安分别检查道路实际等级、连续通路和必要连接，不靠生成图或手工临摹来决定真实几何。主题资源只提供视觉样式，不能成为地理数据来源；基础骨架覆盖范围与地标试验区覆盖分别管理。

首次激活与后续到访的建议可以通过同一份事件序列呈现，不需要人为建立两个内容库。上传完成时间不得替换实际到访时间。内容版本变更需要维护已获得权益，本轮先避免频繁修改已发布试验区。

### 每个候选地标的现场勘察清单

- 核实名称和要拍摄的建筑／标识，保存允许使用的示例素材。
- 选定可停留合影的位置，记录不同出入口与地标的关系。
- 独立配置基础到场校验范围和地图展开多边形。
- 检查道路、河流、城墙等真实边界以及相邻区块接缝。
- 核实主干道入选列表、真实交汇／桥梁及必要通行信息，比较简图与真实详细底图在区域边缘是否对齐。
- 实机采集位置，确认点、底图和区域边界对齐；记录核验日期。
- 明确地标不可用时的展示状态，不承诺未经核实的入口。

## 8. 实测计划与验收

建议每城安排 2 名个人体验者和 2 支 2–3 人小队，每城 6–8 人、双城合计 12–16 人次；另由同一个测试账号完成南京→西安→南京的往返检查。这是首轮操作建议，用于发现流程与实现问题，不作为市场规模或统计有效性的结论。

每城包含站点起步、其他地标起步、至少两个相邻区域、一次转场、一次临时独行、小队一次上传、一次重访、一次结束后重新进入。地点和访问顺序由参与者选择，测试只规定需要覆盖的场景。

| 编号 | 验收场景 | 预期结果 |
|---|---|---|
| A01 | 从车站或其他已配置地标开始 | 两种入口均能完整打卡和开图 |
| A02 | 由近及远浏览 | 列表按照明确的直线距离排序；地图地标位置不移动；无位置时不编造排序距离 |
| A03 | 未展开区移动后激活区域 | 激活前仅主干道简图可见、点仍存在；激活后显示真实详细底图，同一批点与原主干道保持对齐 |
| A04 | 拖动、缩放和切换目标 | 骨架始终可见、未解锁支路和详细内容不泄露；选目标只改变指南针，不自动开图或生成路线 |
| A05 | 南京→西安→南京 | 南京进度、照片及原时间保持；西安独立累计，不串城 |
| A06 | 同城更换账号 | 私有内容与进度隔离；只显示明确授予的共享内容 |
| A07 | 结束旅行后新建旅行、重新登录 | 已获得进度仍在，不同旅行的点和照片可分别回看 |
| A08 | 再次主动打卡，或首次到已展开区域内的另一地标 | 首次／重访按地标判断；重访新增记录且首次时间不改；新地标保存自己的首次事件；新增区域另行计算不重复 |
| A09 | 小队一人提交、重复点击与网络重试 | 成员关联同一事件；只产生一条打卡，不重复上传给每个人 |
| A10 | 独行、会合、加入或退出 | 按第 6 节规则共享；个人点不互相复制；已获得区域不被收回 |
| A11 | 单条公开与撤下 | 地标公共相册正确变化，其他私有内容始终不随之公开 |
| A12 | 弱网和暂时无定位 | 本地内容不丢；未同步状态真实；不把未通过校验说成成功 |
| A13 | 定位样本存在空缺 | 没有连接线、补路线或吸附成假定路径 |
| A14 | 试验区全部展开 | 只显示试验范围完成，不宣称整座城市已全部展开 |
| A15 | 城市尚无任何激活，查看主干道简图 | 真实主干道、必要路名和方位参照可读；普通支路、建筑与 POI 隐藏，主干道可见不增加开图进度 |
| A16 | 简图与详细地图的混合边缘、不同缩放级别 | 主干道、路口、桥梁与点位连续对齐；不出现伪连接、跳位或邻区详细路网泄露 |
| A17 | 已有解锁区时在 C 纸感和藏宝图间切换 | 只改变未解锁简图的样式；已解锁区始终为真实底图，路网、标签、权益、照片与时间不变 |
| A18 | 在不同主题下回放激活前后时刻 | 按当时权益显示简图或真实详细地图；同一批实际采样点原位出现，不补点、不连路线 |
| A19 | 浏览主干道、切换主题或查看未纳入试验区 | 不产生到访或激活事件；试验外区域独立提示，不改变进度分母 |
| A20 | 骨架数据失败、真实底图未加载或内容版本不一致 | 状态真实且可重试；已有记录保留，不用生成路网替代、不泄露被隐藏的详细底图，修复后重新核验对齐 |

验收时记录：打卡尝试与成功数、失败原因、从提交到本人反馈及成员收到的耗时、内容丢失或重复、错误城市归属、迷雾边缘问题，以及用户在哪一步需要额外说明。操作耗时先收集实测数据，再按目标设备和网络建立阈值；不虚构已经达到的指标。

定位生命周期暂缓不等于后续免测。真实外出版本交付前需要单独完成设备记录能力的专项设计与验证，本轮先不展开该议题。

## 9. 建议的制作顺序

1. 地图分层改版：在已有交互原型中加入真实主干道简图、默认 C 纸感和可选藏宝图；已展开区沿用真实详细底图。先验证真实数据筛选、遮罩边缘与坐标对齐，再补主题笔触和纸纹，不直接使用整张概念图作为地图。
2. 城市数据与设备试走：每城先核实核心组，导入真实多边形、地标与主干道配置；在实机上检查位置点、简图与详细地图衔接、跨层路口和合影流程。不能用示意区域或生成道路冒充勘察结果。
3. 真实账号与共享：连接云空间、永久进度、小队关联、同步重试，以及最小公开／撤下流程。
4. 双城内测：按 A01–A20 验收，修复影响闭环的问题，再扩充地标和区划。跨城检查可先用配置测试，现场测试仍分别在两城完成。

“可点击原型”和“可实地使用 MVP”分开验收。模拟成员、照片占位和模拟位置只用于原型，不宣称真实定位、多人同步或云保存已经完成。

后续可直接依据本稿制作页面与实现任务；首批城市内容边界仍需真实现场核实。全城覆盖是长期内容目标，两城小规模试验用于检验同一套产品机制在不同城市中是否准确落地。
