## 可见变化

城市选择与“我的足迹”新增北京、上海、杭州、成都，分别有 16、16、12、16 个旅游解锁组团。代表地标开整区，其余景点保存到访和照片；选城市、看分区、查看普通景点都不自动开图。各城有独立概念封面，明确非实景。

六城共 81 个组团、129 个候选点。新增 92 个点全部带来源和候选位置说明，规划不采用虚构实时热度。完整区域、代表选择理由、来源及内部规划线见[四城规划](four-city-expansion-planning.md)。

原南京、西安完整数据对象、边界及 legacy 权益映射采用扩展前提交的独立哈希校验，确认没有借扩城改写原版本、ID、坐标或权益。SQLite schema 仍为 1，旧数据库可以在新版服务中继续读取并追加新城记录。

首次六城 API 测试出现 Node fetch 在重启后复用旧连接的 ECONNRESET。该测试改为显式新连接并消费响应体，验证两次真实关闭重开，没有用重试掩盖数据断言；产品网络或 SQLite 逻辑未因此放宽。

最终浏览器为 **49 个不同场景通过、0 个失败、0 个未运行**，另有 Vite 六城兼容冒烟。新场景约 1.4 分钟、原同步 46.4 秒、原普通／离线 2.1 分钟、公网 5.6 秒。逐项状态、构建指纹与代表截图见[浏览器摘要](acceptance/six-city-2026-10-02/summary.json)。测试使用 Windows、Chromium 151.0.7922.34 headless 和临时 SQLite，未读取用户真实数据库；默认 `.local-data` 未创建。

除独立公网冒烟外，外链瓦片与字体使用确定性替代资源，避免把公开服务波动混入业务断言；浏览器真实加载和绘制随包六城骨架。公网冒烟另实取 8 张 OSM 瓦片，HTTP 200 且完整解码；不代表四城每处详细底图均已逐地核对。Vite 附加取证最初遇 Chromium 大响应被调试缓冲淘汰、以及脚本未替代外链而受沙箱网络限制，改为独立 HTTP 字节读取并补齐确定性外链后六城重跑通过，产品源码未为测试改变。

最终构建前发现 Vite 会把压缩地图输出为 `beijing.json-HASH.gz`，原 SW 只识别 `.json.gz`。已修复匹配并将回归样例改为真实构建命名；最终 manifest 中四份压缩资产均被接受，API、外部地址和任意数据库 gzip 文件仍被拒绝。重新构建后才执行最终浏览器验收。

## 来源及数据规模

市域与正式区县完整边界已获取并独立审计。北京、杭州、成都的正式区县并集与原市域完全一致；上海区县并集有 9 片超出原市域的残差，构建按原市域裁掉，不缩改市域规避检查。上海原始市域快照含海域，显示面积不能当作官方陆域面积。

主干道与水域为公开 OSM 原始节点，不画假路、不人工封闭断岸。公共 Overpass 服务曾间歇超时，成功分片复用缓存，不使用失败／带 remark 的部分响应。每片来源端点、查询文本、下载时间和 SHA256 保存在最终快照。新增四城采用无损 gzip 减少传输与离线缓存体积；解压后仍是同一原始几何，旧两城快照字节不变。

新增四城地图压缩后共 31,037,097 字节，六城地图资产合计约 63.55 MB；首次离线缓存还需应用与素材。入口 JavaScript 约 6.79 MB（gzip 约 2.12 MB），本轮未用真实慢手机验证解析、绘制与安装耗时。水域源关系中，北京 4 条、上海 1 条、杭州 1 条、成都 4 条因缺少闭合外环或内环无法归属而跳过；原始 ID 与原因保存在快照及[来源摘要](acceptance/six-city-2026-10-02/skeleton-summary.json)，未以假几何补齐。完整覆盖结论针对区域划分和成功查询范围，不代表每一条上游水域关系均可绘制。

另在 VM 执行最终 `dist/sw.js` 的真实 install 逻辑，读取最终 HTML 与 manifest：22 个启动素材合计 76,505,486 字节（约 76.51 MB），六城地图均进入清单，缺失、越界和不存在文件列表均为空，构建 SW 与源码一致。见 [SW 安装审计](acceptance/six-city-2026-10-02/sw-install-audit.json)。首次缓存体积不等于实际线上压缩传输量，也不代表慢网安装耗时已达标。

## 尚需现场或用户环境验证

所有新增入口、村镇／园区／步道代表坐标都仍是候选。有些参照公交站或景区中心，尚未确认是否适合公众拍照、开放或无需预约；需要现场选择实际可达点，再校准 250 米与 GPS 漂移。OSM 行政及路网快照不是官方测绘成果。

本轮使用 Windows 和 Chromium 无头浏览器；窄屏及两个浏览器 context 是模拟。未验证真实手机性能、后台定位、原生相机、掉电／磁盘损坏恢复。同一浏览器资料多标签同时写入尚未提供锁协调。

SQLite 仅在本机回环地址，两个固定资料空间不是认证。没有云账号、正式权限、局域网／公网服务或部署。启动与同步范围见 [README](../README.md) 和 [SQLite 验收](local-database-acceptance.md)。

新增四城地图需要浏览器的 `DecompressionStream` 支持；缺少该能力会显示明确错误，未宣称旧浏览器兼容。首次 PWA 安装必须完成本地素材和地图缓存后才可离线切城；远端详细底图不预缓存。
