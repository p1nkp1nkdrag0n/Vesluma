## 本轮改进

- 定位拒绝、超时、不可用及重试会使旧坐标失效；无回调时 15 秒给出超时提示。照片留在当前页面，恢复定位后可继续。误差超过 100 米、位置超过 5 分钟及模式不一致仍禁止打卡。
- 修正精确 250 米被浮点误差误拒的问题，比较容差仅为 `0.000001 m`，没有扩大原型到场半径。
- 连点保存只产生一条提交；离开打卡页后不会被迟到的照片写入拉回或偷偷增加到访。保存失败保留草稿并可重试；示例图片请求有等待上限，本地选图可以中断它，失败提示说明恢复操作。
- 页面返回和浏览器后退先关闭弹窗，再返回来源页面；分区选择与历史旅程上下文保留，明确“回看这一程”仍打开当前旅程。身份切换后的历史弹窗不会展示上一身份私密照片。
- 主干道请求 30 秒超时后可以重试，迟到结果不覆盖新城市；异地定位不会自动把所选城市地图拉到别处。320 像素窄屏地图控件改为可点击的横排，失败重试提示移出地标面板遮挡区域。
- 已缓存页面遇导航错误或请求／页面内容悬挂时，4 秒后使用缓存入口。未缓存的详细地图瓦片不承诺离线可用。
- 修复了真实浏览器复现的离线白屏：模块请求带 `Origin`，与预缓存响应的 `Vary: Origin` 条件不匹配。恢复仅限当前版本的同源打包静态文件；API 和远程瓦片仍不进入这一缓存规则。

## 尚存的性能范围

本轮模拟的是延迟、错误、无响应和断网下的恢复行为，不是低速带宽或低端手机的性能达标报告。南京／西安主干道 JSON 原始约 19.3／13.2 MB；最终入口 JS 约 2.24 MB（gzip 约 691 KB）。Vite 仍报告超过 500 KB 的 chunk 提示。很慢的首次加载可能超过 30 秒并显示重试；首次缓存未完成时也不能承诺离线可用。后续需要在目标手机与实际网络下单独测量并优化。

## 本地复验入口

```sh
npm test
npm run typecheck
npm run build
npm run test:e2e
```

浏览器验收使用已构建的 `dist`，默认启动或复用 `http://127.0.0.1:4173/`。需要已安装的 Playwright Chromium；已有兼容浏览器时可用 `VESLUMA_QA_BROWSER` 指向它，输出目录可由 `VESLUMA_QA_DIR` 指定。默认截图和诊断文件保存在系统临时目录 `vesluma-pink-qa`，不会把本地旅行照片提交到 Git。

手动试用先运行 `npm run build`，再运行 `npm run preview -- --host 127.0.0.1`，在浏览器打开上述地址。建议流程：

1. 保持“演示位置”，开始南京旅行；普通景点保存到访后确认仍为 0/11；一级地标保存后确认增加一片。
2. 再访同一地标，确认新增照片而开图进度不重复增加；刷新后查看旅程和相册。
3. 查看全市分区、打开地标，再用页面返回／浏览器后退，确认回到原页面；未保存照片离页时取消一次，再确认一次。
4. 切到西安，再返回南京，确认各城进度独立。当前旅行在南京时，西安不能把到访记入南京旅行。
5. 在“位置与体验方式”切换设备模式，拒绝权限后确认不能保存；允许权限并重试。真实设备位置是否在候选地标 250 米内需现场验证。

草稿仅保留在当前打卡页面；离开或刷新会丢弃，界面会说明并在有草稿时提示。已经成功保存的到访、照片、开图进度独立持久化。
